## 1. Base types

```ts
type JsonPrimitive = string | number | boolean | null;
type JsonValue  = JsonPrimitive | JsonValue[] | { [k: string]: JsonValue };
type Row        = Record<string, string | number | null>;
type Unsub      = () => void;

type Topic    = string;   // /^[a-z0-9_.-]{1,128}$/ — ASCII only
type WriterId = string;   // /^[A-Za-z0-9_.:-]{1,128}$/ — ASCII only; host-issued canonical id
type Seq      = number;   // ★per (topic, writer) stream, monotonic from 1, gap-free at the author
type Hlc      = { l: number; c: number };
type EntryId  = [Topic, WriterId, Seq];
type Order    = { l: number; c: number; writer: WriterId; seq: Seq };
type Key      = string;   // register only, UTF-8 ≤512B
```

- `seq`, `hlc.l`, `hlc.c` MUST be non-negative safe integers; `hlc.c` MUST be < 2^32 (stamping that would exceed it fails with `ERR_ENTRY_ENCODING` — a pathological-clock guard). Violations on receive: entry rejected + annotation.
- String comparison is bytewise (SQLite BINARY collation; JS `<` — consistent: ASCII charsets).
- **Total order** `order(a,b)` = lexicographic `(hlc.l, hlc.c, writer, seq)`. Author-stamped hlc is immutable; receivers MUST NOT re-stamp.
- **Per-writer HLC monotonicity**: non-decreasing with seq within a stream; verified at contiguous apply; violation = fork path (§6.4).

## 2. LogEntry

```ts
interface LogEntry {
  topic: Topic; writer: WriterId; seq: Seq; hlc: Hlc;
  kind: string;
  key?: Key;                 // register only
  causal?: [WriterId, Seq];  // register: last write the author observed for the key (§11)
  ref?: EntryId;             // semantic reference (e.g. owned-request origin) — hashed
  payload: JsonValue;        // JSON only; binary via reference strings
  chain: string;             // author-computed (§4), always on the wire
}
```

Local annotations (receiver judgments) live in `sq_annotations` — never on the wire, in exports, in chains, or visible to reducers. Entry ≤ `MAX_ENTRY_BYTES`; frame ≤ `MAX_FRAME_BYTES`.

## 3. HLC

State `(l, c)`; `pt()` = wall ms; `ε = HLC_EPSILON_MS`.

- **Stamp on append**: `l' = max(l, pt()); c' = (l'==l ? c+1 : 0)`.
- **Merge on receive**: merge (standard HLC) **only for entries accepted on first sight** — i.e. entries entering `sq_log` or `sq_pending` after ACL and structural validation, with `hlc.l ≤ pt()+ε`. **Carry rule**: a merge that would push local `c` to 2^32 carries deterministically (`l+1, c=0` — clock state only; entry stamps unaffected). Duplicates, ACL-rejected, malformed, and pre-finality-rejected entries MUST NOT merge (repeated retransmission must not inflate `c`, and unvalidated input must not touch the clock). Over-ε: no merge; annotate `clock_outlier` + `onAnomaly`.
- **Outliers**: stored/ordered as stamped. (a) far-future entries win LWW until real time catches up — operational DoS; host remediation via corrective events; (b) they sit above the finality watermark until their stamp ages into the window — they cannot stall finality, and the authority MAY exclude them when choosing P (safe: the choice replicates via the certificate); (c) sub-ε future stamps are an accepted window; hosts SHOULD alarm on `hlc.l − now > CLOCK_WARN_MS`.

## 4. Canonical encoding and chainHash

**4.1 Purpose — and the trust model this spec rests on.** Chains provide stream integrity, fork detection, and gap verification. **They are not authentication**: entries carry no signatures and `writer` is an unauthenticated string — **any peer granted `full` on a topic can author entries under any writerId**, and under first-applied retention a forged branch that arrives first survives locally until a host directive adjudicates (the system detects divergence; it cannot attribute blame). The security posture is therefore exactly: **all full-sync peers of a topic are fully trusted for its content**; grants (and peerClass) are the containment boundary, and the only unforgeable objects are the signed host artifacts (FinalityCert, WriterDirective, takeover hostSig). Hosts MUST NOT grant `full` to principals they would not trust to write arbitrary content.

**4.2** Canonical JSON = RFC 8785 **JCS**; verification is JCS re-serialization of the parsed value (never substring recovery from frame bytes). Non-representable values: `ERR_ENTRY_ENCODING`. A vetted JCS implementation is an accepted dependency. Strings hash and compare as authored — implementations MUST NOT apply unicode normalization (NFC/NFD) at any point; two keys differing only in normalization form are distinct keys.

**4.3** All hashes lowercase hex, full 64 chars; text UTF-8. `F(x) = u32be(len(bytes)) || bytes`; `dec(n)` = the base-10 ASCII representation of the non-negative safe integer `n`, no sign, no leading zeros (`"0"` for 0):

```
seed(topic, writer) = hex64( sha256( F("seqscribe:v1") || F(topic) || F(writer) ) )
chain(e) = hex64( sha256(
  F(prevChain)                       // first entry: prevChain = seed
  || F(dec(seq)) || F(dec(hlc.l)) || F(dec(hlc.c))
  || F(kind)
  || F(key ?? "")                 || F(key===undefined ? "0" : "1")
  || F(causal ? JCS(causal) : "") || F(causal ? "1" : "0")
  || F(ref ? JCS(ref) : "")       || F(ref ? "1" : "0")
  || F(JCS(payload))
) )
```

Verified at contiguous apply against the previous verified chain; mismatch = fork (§6.4).

## 5. Wire protocol

**5.1** JSON UTF-8, one message per frame, frame ≤ MAX_FRAME_BYTES. The Channel guarantees neither delivery nor ordering (P4).

**5.2 Data lane.** Data messages (ENTRIES, SNAPSHOT, SNAP, DELTA) carry per-connection per-direction monotonic `mid`, **assigned at transmission time (after queue processing)** — queue tail-drops consume no mid, so drops create no mid gaps. Receivers track `recvContigMid`, buffer out-of-order; **ACK `{upTo}` advances only to the contiguous mid**. Senders: unACKed ≤ `INFLIGHT_CREDITS`; **stall = oldest unACKed mid older than `CHANNEL_STALL_MS`** → close (host reconnects; mids/credits/subscriptions reset). Per-peer **data-lane** outbound queue ≤ `SEND_QUEUE_CAP`, overflow drops from the tail (WANT/anti-entropy recover).

**5.3 Control lane.** HELLO, HAVE_GET, HAVE, WANT, PROBE(_RES), FINALITY, WRITER_DIRECTIVE, SNAPSHOT_OFFER/GET, SUB, UNSUB, SUB_ERR, ACK, ERR — outside the mid space, **priority-queued ahead of the data lane and exempt from SEND_QUEUE_CAP** (they are small and bounded). Requests expecting responses (HELLO, HAVE_GET, WANT, PROBE, SNAPSHOT_GET, SUB) retry every `CONTROL_RETRY_MS` until satisfied or close; HELLO unanswered `HELLO_TIMEOUT_MS` → close.

**5.4 Messages.**

```ts
{ t:"HELLO", protoMin:1, protoMax:1, node:WriterId,
  grants: Record<Topic, {mode:"full"|"serve"|"none", schemaHash:string}> }
// proto = min(maxA,maxB) MUST be ≥ max(minA,minB), else ERR_PROTO_VERSION.
// Directional grants; both "full" → mutual full-sync; mine ≥ "serve" → peer may SUB.
// schemaHash (§14 TopicPolicy): differing hash on a mutually-full topic → that topic's
//   sync refused (ERR_SCHEMA_MISMATCH). ACL/peerClass re-verified on every WANT/SUB/
//   ENTRIES received.

{ t:"HAVE_GET", req:number }
// One GET requests the FULL round (all pages 1..of). GET has no page field —
// partial page loss is recovered by retrying the GET (CONTROL_RETRY). A retry with
// the SAME req MUST return the identically captured round (pages snapshotted at first
// processing) — otherwise pages from different moments could be assembled. Captures are
// per-connection and only the latest is retained: a GET with a new req discards the
// previous capture.
{ t:"HAVE", req:number, page:number, of:number,
  vectors: Record<Topic, {
    fgen?: number,                                  // ★latest finality generation held
    writers: Record<WriterId, {contig:Seq, chain:string, rgen?:number}
                             | {retired:true, finalSeq:Seq, finalChain:string, rgen:number}>
  }> }
// ★HAVE is response-only (to HAVE_GET) — loss recovery rides CONTROL_RETRY of the GET.
//   Sent at connect and every ANTI_ENTROPY_MS round.
// ★Tombstones are a DERIVED CACHE of writer directives (§13) — never authoritative.
//   Live entries carry rgen when a directive history exists, so retire/unretire freshness
//   is comparable in both states.
// ★fgen lag rule: if peer's fgen < mine, push my latest FINALITY for the topic;
//   if mine is lower, expect theirs. This is the certificate repair path (§7).

{ t:"WANT", req:number, topic, writer, fromSeq:Seq }
{ t:"ENTRIES", mid, req?:number, topic, writer, fromSeq:Seq, toSeq:Seq,
  entries:LogEntry[], done:boolean }
// toSeq = the responder's contig captured when processing the WANT — a stable completion
// point under continuous appends. done=true on the batch reaching toSeq.

{ t:"PROBE", topic, writer, seqs:Seq[] }
{ t:"PROBE_RES", topic, writer, points:{seq, chain}[], unavailable?:{belowSeq:Seq} }

{ t:"FINALITY", topic, cert:FinalityCert }
{ t:"WRITER_DIRECTIVE", directive:WriterDirective }

{ t:"SNAPSHOT_OFFER", topic, snapshotId:string, order:Order,
  cut:Record<WriterId,{seq,chain}>, certHash:string }
{ t:"SNAPSHOT_GET", topic, snapshotId, wants:{name,version}[] }
{ t:"SNAPSHOT", mid, topic, snapshotId, chunk:number, of:number, data:string,
  totalHash?:string }
// snapshotId = sha256(JCS(SnapshotBody)) — deterministic, immutable, self-binding.
// Chunking is BYTE-LEVEL over JCS(SnapshotBody): split ≤ frame budget (base64 `data`),
// reassemble by (snapshotId, chunk), dedupe, buffer out-of-order, parse ONLY after all
// chunks and sha256(bytes)==totalHash. Missing chunks → re-GET. Consumers MUST verify
// certHash == sha256(JCS(their locally verified FinalityCert)) before adopting;
// ★a consumer holding NO verified cert for the topic MUST NOT adopt a snapshot —
// it first obtains FINALITY via the fgen repair path (§7.8 ordering).

{ t:"SUB", subId, view:string, params:JsonValue, fromCursor?:string }
{ t:"SNAP", mid, subId, chunk:number, of:number, data:string, cursor:string,
  reset:boolean, totalHash?:string }
// ★SNAP bodies use the same byte-level chunking rule as SNAPSHOT (rows serialized as
//   JCS of the rowKey-sorted row array).
{ t:"DELTA", mid, subId, changes:{upserts:Row[], deletes:string[]}, cursor:string }
// DELTA is never chunked: a delta whose serialization would exceed MAX_FRAME_BYTES
// downgrades that subscriber group to SNAP(reset=true).
{ t:"UNSUB", subId }
{ t:"SUB_ERR", subId, code:ErrCode }
{ t:"ACK", upTo:number }
{ t:"ERR", code:ErrCode, ref?:string, detail?:string }
```

## 6. Tier-1 synchronization

**6.1 contig.** Replica stream state = verified contiguous prefix head. Out-of-order → `sq_pending` (cap `PENDING_CAP`; overflow drops; WANT recovers). On contig+1: verify chain → apply → advance → drain.

**6.2 Loop.** READY → HAVE_GET ⇄ HAVE (paginated; retried) → WANT per deficit (fromSeq = contig+1, ≤4 concurrent) → ENTRIES → 6.1. Application idempotent by UNIQUE (topic,writer,seq); **same-id-different-content = fork path, never a silent skip** (ingest, sync, and import alike).

**6.3 Eager push & relay.** On local append: ENTRIES direct to K mutual-full READY peers (most-recently-active bucket; lexicographic peerId tiebreak), batched by `flushThrottleMs`. **Relay (path-independent)**: on applying any entry whose `hlc.l ≥ now − RELAY_WINDOW_MS`, relay it once to `RELAY_FANOUT` mutual-full peers excluding the sender, selected by the same deterministic rule. (Receive-path tracking is not required and not specced — recency is the criterion.) Duplicates are harmless; relays ride the data lane within credits.

**6.4 Fork detection.** ① chain mismatch at apply ② HAVE contradiction (same seq different chain; peer contig ≤ mine with differing chain) ③ same-id-different-content ④ per-writer HLC monotonicity violation. On detect: keep first-applied branch (never switch), seal `'fork'`, reject the stream, `onAnomaly('writer_forked')`, PROBE to locate the last common point (bounds §12 recovery). P1/P2 exclude forked tails until a §12 directive.

## 7. Finality

**7.1 Model.** Independent per-node cut advancement diverges (nodes disagree on accept/reject) and is forbidden. Finality is decided by a **topic authority** and distributed as a signed, replicated, monotone certificate.

**7.2 Certificate.**

```ts
interface FinalityCert {
  topic: Topic;
  order: Order;               // watermark P — THE normative judgment
  cut: Record<WriterId, {seq: Seq, chain: string}>;   // projection of P; absent writer ⇒ seq 0
  generation: number;         // strictly increasing per topic; reuse forbidden — a second
                              // cert with an equal generation and different content is
                              // rejected + onAnomaly('bad_cert')
  authority: string;          // stable authority ID (a role, not a node — see 7.3)
  sig: string;
}
```

**P = the total-order maximum among entries the authority holds satisfying `hlc.l ≤ now − FINALITY_WINDOW_MS`** (de-circularized definition). **If that set is empty, no certificate is issued and no advancement occurs** (max of an empty set is undefined). `cut[w].seq` = w's last seq with order ≤ P; **a writer absent from `cut` has cover seq 0** — all its entries at order ≤ P are outside the cover. `certHash` of a certificate is defined once: `sha256(JCS(cert))`.

**7.3 Authority.**
- A **stable identity decoupled from any node** (e.g. `"adhdev:coordinator"`) — key management and rotation of the machine behind it are the host's concern (via `verifyFinality`); **changing the authority id itself is a schema change** (it is part of topicSchemaHash → fleet upgrade procedure).
- The authority MUST be a **full replica of the topic** — it can only certify entries it holds. Consequently a metadata-class peer (e.g. ADHDev cloud) **cannot be the authority of a content topic**; for ADHDev, content topics are certified by the coordinator, metadata topics may be certified by the cloud.
- Finality progress is bounded by the authority replica's freshness; a stalled authority stalls finality regardless of the window. Cut-stall diagnosis order: authority replica stale/offline? → empty qualifying window? → outlier-exclusion policy at the frontier? (Dead writers do NOT block P under the certificate model — the authority certifies what it holds; retire them anyway so their returning tails fail cleanly rather than surprisingly.)
- A topic without a configured authority never finalizes (and never compacts) — valid for small topics.

**7.4 Issuance & propagation.** The library computes, the host signs: **`proposeFinality(topic)` returns `Omit<FinalityCert,"sig">`** (P and cut computed per 7.2 over the local replica — hosts never reimplement 7.2); the authority host signs it and calls `ingestFinality(cert)` — which applies it locally and pushes FINALITY to all READY peers. Repair path: HAVE carries per-topic `fgen`; on observing a lower peer fgen, push the latest cert (anti-entropy rounds make this eventually reliable); a node entering READY learns lag from the first HAVE exchange. Nodes accept only strictly-increasing generations from the topic's configured authority, verified via `verifyFinality`.

**7.5 Enforcement & quarantine.** With local cert (P, cut):
- Ingest: reject entries with `order(e) ≤ P` not inside the cover (`ERR_PRE_FINALITY` + onAnomaly).
- On accepting a higher cert: (a) quarantine applied entries with `order ≤ P` and `seq > cut[w].seq` (non-canonical late region). **This transition is fully defined**: contig rewinds to `cut[w].seq`; the quarantined seqs remain permanently consumed (the (topic,writer,seq) namespace is never reused); the stream seals `'fork'`-equivalent (`onAnomaly('writer_forked')`) — its author's subsequent appends chain from quarantined entries no node can verify, so **only a WriterDirective resolves it** (§12: canonicalize at the cut, author continues under a new writerId). The author's own node applies the same rule to its own stream; (b) **where local `contig ≥ cut[w].seq`, verify the local chain at `cut[w].seq` equals `cut[w].chain`** — a mismatch means the local prefix diverged inside the covered region (a fork the cert reached before detection): route to the §12 recovery procedure (quarantine to last matching point, rewind, re-fetch canonical); after such cert-driven recovery **the stream remains `'fork'`-sealed awaiting a WriterDirective** (§18). Local `contig < cut[w].seq` is NOT a mismatch — the topic is in the **"verified, basis pending"** state (cert held, coverage catching up via sync/bootstrap); (c) rebuild affected views from the snapshot/checkpoint at or before the cut. All nodes converge to: canonical covered prefix + live post-P region.
- **Provisional delivery**: entries delivered to `onEntry` before finality are provisional. When a cert quarantines an already-delivered entry, the library emits `onAnomaly({kind:"entry_quarantined", entry})` per entry; **the anomaly is a volatile callback and is NOT a reliable compensation channel** (an offline consumer misses it) — consumers with irreversible side effects MUST use finalized-only consumption (gate on `finality(topic)`, consuming only entries at order ≤ the local watermark); compensation-on-anomaly is best-effort hygiene, never the correctness mechanism. **Latency consequence (explicit)**: finalized-only consumption waits up to FINALITY_WINDOW_MS (default 30 days) — finality exists for **compaction safety**, not consumer ordering. Most consumers are provisional by design; a consumer that is both irreversible and timely needs host-level compensation, and no spec mechanism removes that trade-off.

**7.6 Compaction — two separate disciplines.** (1) **Certificate effects are immediate**: enforcement and quarantine happen on cert acceptance. (2) **Cold archiving lags locally**: moving pre-P entries to `archive/<topic>.jsonl.gz` (local only) waits until every registered `onEntry` consumer's cursor passes them; a consumer idle past FINALITY_WINDOW_MS is dropped (`onAnomaly('consumer_abandoned')`), and its later resume resets its cursor to the first post-cut rowid. Cut state = permanent base checkpoint; pre-P checkpoints prune.

**7.7 SnapshotBody.**

```ts
interface SnapshotBody {
  topic: Topic; order: Order; generation: number;
  certHash: string;    // = sha256(JCS(FinalityCert)) — the single binding definition;
                       // consumers verify it against their locally verified cert
  cut: Record<WriterId, {seq: Seq, chain: string}>;
  directives: WriterDirective[];         // ★the SIGNED directive originals current at
                                         // snapshot time — authority lives only in
                                         // directives (§13); unsigned lifecycle fields
                                         // in a snapshot would act as forgeable
                                         // retirement, so none exist here
  register?: RegisterSnapshotState;      // §11.6 — full reducer state, never a value map
  views: {name: string, version: string, state: JsonValue, stateHash: string}[];
}
// Bootstrap: verify every directive's signature (authority.verifyWriterDirective) →
// adopt the highest rgen per (topic, writer) → store in sq_directives → rebuild the
// sq_writers lifecycle cache. A writer with no directive is rgen 0, live. A local
// 'fork' seal is a LOCAL judgment and NEVER replicates via snapshots.
```

**7.8 Bootstrap.** **Ordering rule: a node MUST NOT issue WANTs below a topic's cut before holding a verified certificate for it** (topics with no authority are exempt — they have no cut). The connect sequence is: HAVE exchange → fgen lag repair (FINALITY push) → then snapshot. Flow: WANT below the cut → SNAPSHOT_OFFER → SNAPSHOT_GET (wanted view versions) → SNAPSHOT (chunked; certHash verified) → ENTRIES replay from the cut (chains continue from cut chains); writer lifecycle restores from the snapshot's signature-verified directives (§7.7). A view absent at matching version: starts from init at the cut, flagged `bootstrapPartial`; the host MUST provision full state if completeness is required (a version bump with no pre-cut logs anywhere makes this permanent — host's responsibility).

**7.9 Ring topics** are exempt from finality, archive, and snapshots.

## 8. Storage — SQLite DDL

Single file `seqscribe.db`, WAL. `durability`: `"normal"` (power-loss window per SQLite/OS semantics under synchronous=NORMAL) | `"full"`. **Single-process ownership MUST** (adapter lock, §14 `SqliteHandle`; `ERR_DB_OWNED`).

**Write path**: single append queue, group commit (GROUP_COMMIT_MS/N); `append()` resolves after commit. **Certificate and directive application is serialized through this same queue**: enqueued-but-uncommitted appends on a stream that a cert/directive seals or quarantines are rejected (promises reject with ERR_WRITER_SEALED) — never committed onto a quarantined chain. Materialization/checkpoints/annotations async. **Re-entrancy**: callbacks MAY `append`; appends from callbacks enqueue asynchronously — synchronous re-entry into the commit queue MUST NOT occur.

## 9. Views

```ts
interface ViewDef<S extends JsonValue, R extends Row> {
  version: string;
  init: S;
  reduce: (s: S, e: LogEntry) => S;     // pure, deterministic, non-mutating
  rows: (s: S) => Iterable<R>;          // pure; order meaningless — stored sorted by rowKey
  rowKey: string;                       // canonicalized to TEXT
  schema: Record<string, "TEXT"|"INTEGER"|"REAL">;   // identifiers /^[a-z_][a-z0-9_]*$/, quoted
  delta?: (s: S, e: LogEntry) => {upserts: R[], deletes: string[]};
      // s = PRE-apply state; describes rows(s)→rows(reduce(s,e)).
      // rows() is authoritative; delta an optimization — verified at each checkpoint via
      // sha256(JCS(sorted rows)); mismatch → rebuild + SNAP reset + onAnomaly('delta_mismatch')
  fts?: string[];
}
```

- S round-trips JCS (no Date/Map/bigint/classes). `stateHash = sha256(JCS(state))`.
- Row values containing NaN/Infinity are rejected before JCS (materialization error → view faulted).
- A serialized row MUST fit `MAX_ROW_BYTES`; a violating row fails materialization for that view → view marked faulted (`onAnomaly('view_faulted')`, queries error) until rebuilt with a fixed definition.
- Tables: `sqv_<sanitized>_<sha256(name)[:8]>`; register built-ins `sqv_reg_<sanitized>_<sha256(topic)[:8]>`.
- Views without `delta`: SNAP-only serving.
- **Ring topics accept no custom ViewDefs and have no SQLite views** (§7.9). They expose exactly one built-in subscribable view, **`tail`** — rows are entry projections `{writer, seq, hlc_l, hlc_c, kind, payload}` keyed by `"writer:seq"` — served from the in-memory ring. Restart = new epoch → SNAP reset.
- Pipeline: async; late arrivals restore the checkpoint before p and recompute the suffix (queryable during; atomic swap; epoch bump). Pre-watermark positions cannot reach this path.

**`onEntry` (at-least-once, serial):** per consumer, callbacks run serially in rowid order; the cursor advances only after the callback's promise resolves; failure → no advance, retried with backoff. Cursor resume after abandonment: first post-cut rowid.

## 10. Subscriptions

Serving state per (view, JCS(params)) group: in-memory delta journal (`SUB_DELTA_RETAIN`), monotonic `deltaSeq`, `epoch` — minted from the node's RNG at each materialization revision/process start. **RNG is injectable** (`opts.rng`) — the harness injects a seeded RNG so epochs are deterministic under P5; production defaults to crypto randomness. Cursor = opaque `{epoch, deltaSeq}`. re-SUB: epoch match ∧ within retention → DELTA resume; else SNAP reset. Cursor ahead of current = ERR_FUTURE_CURSOR → discard, SUB fresh. "Compute once, broadcast" applies within one group.

## 11. Register semantics

**11.1** Kinds: `append` | `register`. Register topics: `conflict.default` omitted ⇒ **lww**. **Raw `log(topic).append()` on a register topic throws** (`SeqscribeError` `ERR_MISUSE`) — register writes go only through helpers (the library stamps `causal`; a hand-rolled causal would corrupt concurrency judgment).

**11.1b Wire vocabulary (normative — two implementations must produce identical chains):**

| Helper | kind | payload (JCS) |
|---|---|---|
| set | `"set"` | `{"value": v}` |
| del | `"del"` | `null` |
| add | `"add"` | `{"member": m}` |
| remove | `"remove"` | `{"member": m}` |
| resolve | `"resolve"` | `{"supersedes": EntryId[], "value": v}` |
| resolveMember | `"resolve-member"` | `{"member": m, "supersedes": EntryId[], "present": bool}` |
| chown | `"chown"` | `{"newOwner": w}` |
| takeover | `"chown-takeover"` | `{"newOwner": w, "hostSig": s}` |
| request | `"request"` | `{"value": v}` (owner via `ownerOf` at materialization; `ref` on the approving set) |

**`resetGen` is NOT an authored field** — it is derived by the reducer from the total order alone and appears in no payload (an authored resetGen could lie).

**11.2 Causal stamping (race-safe).** Per key, *last observed* = the later of (a) the materialized winner and (b) the tail of the author's own not-yet-materialized (incl. uncommitted) appends for that key. Stamping from the materialized table alone is forbidden.

**11.3 Concurrency.** causal = single pointer; concurrency = causal-ancestor reachability (recursive walk; direct comparison misses transitivity). Multi-branch observation is expressible only via `resolve(supersedes)` (v1 limit; version vectors = proto v2).

**11.4 Key-level policies** (`set/del/chown/resolve` operate at key level):
- **lww**: last in total order (the only causality-independent policy).
- **fww**: fold in total order; adopt iff causal successor of the current adoptee; keep the earlier when concurrent.
- **resolver**: provisional winner by lww; resolution only via appended resolve events; concurrent resolves settle by lww; a set concurrent with a resolve (outside its supersedes) **is settled against the resolve outcome by lww**.
- **owned**: only the owner's writes materialize; violations annotated. Requests via `reg.request`; approval appends a set with `ref` = request id; expiry is query-time derivation (`pendingRequests(topic, now)`); takeover entries verified via `authority.verifyTakeover`.

**11.5 Member ops (`add/remove`) — per-member sub-registers + reset generation.** Each `(key, member)` is an independent sub-register folded by the key's policy at member granularity (concurrent `add("x")`/`add("y")` both survive; fww on a key means fww per member). **Causal scopes differ by op class**: key-level ops (`set/del/chown/resolve`) stamp and judge causality at key scope; member ops stamp and judge at **(key, member, resetGen)** scope — **causal pointers are interpreted under the resetGen derived at that entry's own position in the fold** (a late-arriving del re-derives epochs for subsequent positions; two implementations must not read causal under different epoch views) — a `remove("x")` chains from the last observed op on member "x" in the current reset epoch, not from whatever key-level op came last. `request` entries participate in neither winners nor frontiers.
- `del(key)` is a **reset epoch**: it bumps resetGen; member ops from before it (by total order) never resurrect. **Only a materialization-effective del/set bumps resetGen** (under owned: the owner's; under fww: the adopted one) — otherwise a non-owner could reset a member set by firing ignored dels.
- **Mixing scalar and member ops on one key** (deterministic mirror rules, no per-key mode declaration): `set(key, value)` on a key holding members **replaces the whole member map** — clears members, bumps resetGen, establishes the scalar value. Symmetrically, a member op on a key in scalar state **clears the scalar and starts a member set, bumping resetGen**.
- Conflict callbacks fire at the colliding unit's granularity: key for key-level, `(key, member)` for member ops (`Conflict.member` set). Member conflicts resolve via `resolveMember(key, member, supersedes, present)` — the resolved value of a member sub-register is boolean presence.

**11.6 Snapshot state** (winner/owner/frontier preserved — a value map breaks P2 and `ownerOf` post-bootstrap):

```ts
interface RegisterSnapshotState {
```

**11.7 Override globs.** Patterns are exact keys or prefix globs (`prefix.*` — a literal prefix followed by `.*`; no other wildcard forms). Precedence: exact match > longest matching prefix. ## 12. Fork canonicalization

First-applied retention leaves nodes on different branches; a new writerId rescues only new work. Canonicalization is a **WriterDirective** (§13) with `state:"retired"`, `finalSeq`, `finalChain` — the host declares the canonical branch. On acceptance, a node whose stream disagrees (chain at finalSeq differs, or entries beyond finalSeq) runs the **recovery transition**:

1. quarantine the divergent suffix back to the last matching point (PROBE evidence bounds it),
2. rewind `contig` to that point,
3. recovery-WANT the canonical `point+1 .. finalSeq` from any peer holding it (or adopt a canonical snapshot if none) — **canonical-prefix ingest during recovery passes through the `'fork'` seal** (the seal otherwise rejects the stream; without this exception step 3 is blocked by its own rule). **Absorbing state**: if every peer is exhausted and no canonical snapshot exists, the stream remains sealed with contig at the last common point and `onAnomaly('canonical_unavailable')` fires; the host's escapes are a superseding directive (higher rgen) with `finalSeq` = that point — shrinking canonical to what actually exists — or leaving the seal permanent,
4. verify chains up to `finalChain`,
5. then seal `'retired'` (a directive supersedes a `'fork'` seal; the recorded `rgen` is the directive's).

**The "last common point" is per-node** — nodes may have diverged at different heights; the host MUST set the directive's finalSeq to the minimum divergence point across affected nodes (gathered from their PROBE evidence / anomaly reports — collection is explicitly the host's job). Leaving a fork unresolved (permanent §20 exclusion) is the host's prerogative.

## 13. Writer directives & retirement

```ts
interface WriterDirective {
  topic: Topic; writer: WriterId;
  state: "live" | "retired";
  rgen: number;                 // strictly increasing per (topic, writer)
  finalSeq?: Seq; finalChain?: string;    // required when state=="retired"
  authority: string; sig: string;
}
```

- **Authority lives only in directives** — HAVE tombstones and `sq_writers` fields are derived caches. Directives travel via WRITER_DIRECTIVE (pushed on issuance; repaired via HAVE rgen comparison — a peer advertising a lower rgen gets the latest directive), verified via `authority.verifyWriterDirective`, stored in `sq_directives`.
- Peers honor the highest rgen for either state (this is what makes retire/unretire deterministic against stale caches). **Two directives with equal rgen and different content = `onAnomaly('bad_directive')` and both are refused** pending host intervention.
- **The normative artifact APIs are `publishWriterDirective(d)` (signed artifact in) and `ingestFinality(cert)`.** The core never signs. `retire(writer, {chownTo?})` is host-side sugar: it builds **one unsigned directive per topic where the writer has a stream** (a directive is per-(topic, writer); finalSeq/finalChain are the per-topic stream heads, computed by the library), passes each to the injected `authority.issueWriterDirective` for signing, and publishes them — `retire()` throws if no issuer hook is configured. Fork canonicalization always goes through `publishWriterDirective` directly (the host chooses the canonical finalSeq/finalChain there). **Scope**: directives cover the writer's existing streams; nothing prevents a retired writer from starting a stream on a new topic — **writer-wide bans are host identity management, not directive machinery** (writerId is host-issued: stop issuing it and reject it at attach/ACL). Owned keys bulk-chown (takeover path if no target); grace `RETIRE_GRACE_MS`; `unretire` issues a `state:"live"` directive with rgen+1 (never applicable to an unresolved `'fork'` seal without a canonicalizing retired-directive first). Streams absorb into the cut at the next certificate after grace.
- Entries beyond finalSeq, or mismatching finalChain, are rejected + onAnomaly. HAVE stops exposing tombstones after `TOMBSTONE_RETAIN_MS`, but `sq_writers`/`sq_directives` rows persist forever (§8) — no resurrection at day 401.

## 20. Non-normative appendix — known limitations (accepted)

1. Single causal pointer (multi-branch via resolve; vectors = proto v2).
2. chain ≠ authentication; authority = signed artifacts only.
3. Sub-ε future-stamp window (alarms mitigate).
4. Fork divergence window until a §12 directive; hosts may accept permanently.
5. Finality rejection loses genuinely-late data (P3 exception) — **and the writer identity with it**: a writer offline beyond FINALITY_WINDOW_MS whose tail is finalized-out returns to a post-cut quarantine → `'fork'`-equivalent seal, and continues only under a new writerId (owned keys bulk-chown; causal pointers and member frontiers reset with the identity). Hosts whose fleets routinely sleep past the window must size it accordingly. Topics without an authority never finalize or compact.
6. add/remove is per-member with reset generations — not observed-remove.
7. JCS is an accepted dependency.
8. **Storage sizing (non-normative)**: every full replica holds all pre-finality entries for the window — at the P7 profile (10 writes/s fleet-wide, 30-day window) that is ~26 M rows per topic-complete replica. Hosts size FINALITY_WINDOW_MS and partition topics via grants accordingly.
9. **Authority-id rotation is a fleet schema change**: the authority id is part of topicSchemaHash, so replacing it (e.g. the coordinator machine dies unrecoverably and its role identity cannot be re-keyed) halts finality and compaction until a coordinated fleet upgrade. Key rotation behind a stable id is the host's mitigation; id rotation is deliberately expensive. **Generation counters are part of the authority's durable state**: restoring the authority host from an old backup rewinds generation and the fleet rejects every new cert as `bad_cert`. Before issuing after any recovery, the authority MUST re-learn the fleet's highest known generation (HAVE `fgen`) and continue above it.
10. P7 proves catch-up, not sustained-envelope soak (§19).
