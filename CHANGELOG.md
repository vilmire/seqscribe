# seqscribe SPEC changelog

Newest first. Each amendment names what it changed and why, including its own mistakes.

**v3.5 (first integration-surfaced amendments — 25 items, embedded not simulated)**: ratified [docs/proposals-v3.5.md](docs/proposals-v3.5.md) P1–P25, surfaced by the first production embedding (a long-running mixed-platform fleet) rather than by document review or the P7 gate — the third distinct discovery path, after v3.3's vector/harness construction and v3.4's failing runs. Grouped: **wire hardening** (§5.2 over-credit receiver remedy; §5.4 `MAX_REASSEMBLY_BYTES` total bound on all three chunked reassemblies, delta-aware so honest retransmission never trips it; wire-level `__proto__` rejection; `SUB.params` optional) · **liveness** (§6.2b WANT completion MUST detect non-progress — the finality-rejection branch re-queued the identical request with no delay and no progress test, an absorbing state that pinned a fleet daemon at 100% CPU while every point-in-time gauge read healthy) · **ownership** (§8.1 crash-surviving enforcement, idempotent per-handle acquire, multi-process IPC boundary) · **host surface** (§9.1 durable-consumer reset/delete/caught-up; §9.2 bounded scans; §14.1 the whole extension API as normative-in-shape) · **observability** (§14.1 `stats()` with cumulative reject histogram and interval throughput counters, §16 `SYNC_HOT_*`). **Ratification recorded the implementation, not the proposal** — where the two disagreed the SPEC follows the code, and **two proposed amendments were deliberately NOT ratified** because the shipped code does not satisfy them: P6's distinct `ERR_PROTOCOL` (the remedy is normative; the ERR still rides `ERR_ENTRY_ENCODING` — a new code would change frames a v3.5 peer parses) and P8's exclusion of `__proto__` from the §1 charters (only the wire-level rejection is normative; `TOPIC_RE`/`WRITER_RE` are unchanged). Both are recorded in the SPEC as explicit deferrals so a second implementation matches the first rather than the aspiration — and leaving the charters alone is why v3.5 changes no hash: the test vectors remain valid unchanged. **Mistake owned**: P21 shipped a `ScanResult.complete` field its own status marker never mentioned, and described the writer form as "hot + archive" three weeks before P25 proved that omitted a ring topic's only retained entries — the status markers were written as implementation notes and were not a reliable specification of what shipped, which is why ratification re-derived every claim from source and found five further divergences (recorded per-item in the proposals file's ratification map).

**v3.4 (first P7-gate amendments — 4 items, measured not reviewed)**: ratified [docs/proposals-v3.4.md](docs/proposals-v3.4.md) after the full §19 P7 profile (100 nodes / 200 topics / 60 s partition / 1% loss) failed and was driven to heal+40 s — ① §6.3 hlc-window relay replaced by knowledge-based push (per-session peer stream-head knowledge + capacity-aware dirty pump; RELAY_WINDOW_MS/RELAY_FANOUT retired). **Mistake owned**: v3.1's claim that "control retries + eager relay fan-out fixes the anti-entropy-vs-P7 arithmetic" was wrong — the hlc recency criterion cannot gossip partition-aged backlogs, and post-heal repair measured at one hop per anti-entropy round (never converged in 400 s) ② §5.2 gains same-mid retransmission of unACKed data frames at CONTROL_RETRY_MS cadence — a single lost frame otherwise head-of-line blocks the receiver until the 30 s stall close, and P7's 1% loss made that the dominant convergence cost ③ §19 P7 pinned to a host-visible partition; §20.11 states the silent-partition bound (≤ ANTI_ENTROPY_MS) explicitly ④ §8 `sq_log.rowid` → AUTOINCREMENT — SQLite rowid reuse after §7.6 archiving dropped new entries below every cursor and view watermark (v3.2 specified both §7.6 and the DDL without noticing they conflict).

**v3.3 (implementation-start amendments — vector/harness findings, 4 items)**: ratified [docs/proposals-v3.3.md](docs/proposals-v3.3.md) P1–P4, surfaced not by document review but by the two activities v3.2 itself named as the discovery path (known-answer vector generation, harness design) — ① `timers` injection added to `createSeqscribe` (P5 seed determinism was unimplementable: `clock()` made time readable deterministically but not *schedulable* deterministically — six constants schedule future work through what would have been wall-clock `setTimeout`) ② topicSchemaHash's exact normalized object pinned (v3.2 fixed the hashed field *set* but not its shape; two conforming implementations could disagree on every hash, and the hash gates sync) ③ one sentence forbidding unicode normalization (bytes-as-authored was implied, never stated) ④ `dec()` defined (was used undefined in §4.3). Mistake owned: v3.2's claim that remaining defects would surface as *failing seeds* was half right — two of these four were API-surface defects a seed could never reach because the harness couldn't be built without them.

**v3.2 (round 6 — one review)**: two state-machine holes closed — ① post-cut quarantine of a stream's applied tail now has a defined transition (contig rewinds to the cut; the stream seals 'fork'-equivalent; consumed seqs stay permanently reserved; only a WriterDirective resolves it — previously the stream bricked: its next seq chained from quarantined entries no node could verify) ② §12 step 3 gains an absorbing state (canonical source exhausted → sealed at LCP + `canonical_unavailable`; host escape = a superseding directive with finalSeq=LCP, shrinking canonical to what exists). Also: mids assigned at transmission time (queue drops consume no mid); causal interpreted under the fold-position resetGen; authority-id rotation cost added to §20; error model (`SeqscribeError.code`, sync-throw/async-reject, `ERR_MISUSE`) and `Conflict` as a discriminated union; retire() scope clarified (directives cover existing streams — writer-wide bans are host identity management). **Framing correction**: round 5's "no new mechanisms" claim was inaccurate — `resolveMember`, `issueTakeover`, `finality()`, per-member frontiers were new API surface; this document stops using that framing.

**Closing amendment (round 5 — three reviews)**: SnapshotBody carries the **signed WriterDirective originals** instead of derived lifecycle fields (an unsigned `seal` in a snapshot would act as a forgeable retirement directive, and a local `'fork'` judgment must never replicate — supersedes the round-4 form); `issueWriterDirective` fills authority+sig with library-side match verification; takeover issuance wired (`AuthorityHooks.issueTakeover` + `RegisterHandle.takeover` — previously unproducible under the raw-append ban); normative register wire vocabulary (kind/payload table; resetGen is reducer-derived, never authored); scalar↔member mirror rules; per-member frontier/superseded; `Conflict.resolveMember` (and `resolve()` throws on member conflicts); `finality(topic)` getter (the gate for finalized-only consumption); `entry_quarantined` demoted to best-effort hygiene; HAVE_GET same-req = identical captured round; "verified, basis pending" state; types.d.ts export + fixture-import CI; errata (§20 reference, ms values).

Freeze amendment (round 4 — three reviews): SnapshotBody carries writer lifecycle (rgen/seal/finalSeq/finalChain — without it bootstrap resurrects retired writers and P1 breaks on the writer-lifetime axis); publish/ingest confirmed as the normative artifact APIs with propose/issue helpers (`proposeFinality`, `AuthorityHooks.issueWriterDirective`; `retire()` = per-topic sugar); member-op causal scopes ((key, member, resetGen)) + scalar/member mixing rule + `resolveMember`; ring/none stream-head persistence (EntryId uniqueness across restarts); provisional `onEntry` delivery + `entry_quarantined` anomaly; types.d.ts generation rule (all normative ts blocks concatenated); plus one-line closures (empty-window cert, HAVE_GET whole-round retry, fork-seal pass-through in recovery, cert-vs-catch-up distinction, DELTA overflow downgrade, normalized-policy schemaHash, HLC c-carry, re-defineTopic immutability, naming alignment).

v3→v3.1: ① `WriterDirective` — signed, wire-carried authority for retirement/canonicalization (HAVE tombstones demoted to derived cache) + the five-step fork recovery transition ② finality issuance (`ingestFinality`) + propagation repair (per-topic generation in HAVE, resend on lag) + covered-region chain verification at certificate acceptance ③ authority constraints (full replica; stable authority id decoupled from nodes; content topics cannot be certified by a metadata-class peer) ④ register member-op semantics (per-member sub-registers + key reset generation) and glob matching fixed ⑤ HAVE becomes request/response (`HAVE_GET`); ENTRIES carries `fromSeq/toSeq` ⑥ SNAP adopts byte-chunking; `snapshotId = sha256(body)`; `certHash` binding ⑦ `cut[w]` absent = seq 0 ⑧ compilable types incl. realistic `SqliteHandle` with ownership lock ⑨ P1 batch (at-least-once `onEntry`, permanent writer registry, import chain verification, HLC merge ordering, control-lane priority, MAX_ROW_BYTES, NOT NULL ord_*, injected RNG for P5).
