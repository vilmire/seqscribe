## 1. JCS (RFC 8785) — integration checks

The vetted JCS dependency (SPEC §4.2) is trusted for correctness; these cases verify the *integration* (that the library actually routes values through JCS, with ES number serialization and UTF-16 code-unit key ordering).

| Input (JS literal) | JCS output |
|---|---|
| `{}` | `{}` |
| `[]` | `[]` |
| `{b:2, a:1, A:0}` | `{"A":0,"a":1,"b":2}` |
| `{"é":1, z:2}` | `{"z":2,"é":1}` — `z` (U+007A) sorts before `é` (U+00E9) |
| `{x:[1, null, {y:false}]}` | `{"x":[1,null,{"y":false}]}` |
| `42` | `42` |
| `-0` | `0` |
| `0.1` | `0.1` |
| `1e21` | `1e+21` |
| `1e-7` | `1e-7` |
| `9007199254740991` | `9007199254740991` |
| `"a\"b\\c\nd\te\u0001f"` | `"a\"b\\c\nd\te\u0001f"` — two-char escapes where they exist, `\u0001` otherwise |
| `"héllo ✓"` | `"héllo ✓"` — **no unicode normalization**: bytes hash as authored (NFC vs NFD produce different chains; see §8 finding F4) |

## 7. `topicSchemaHash` (normalization per SPEC v3.3 §14)

Normalized object: `{kind, conflict, registerSemanticsVersion: 1, finalityAuthority}` where `conflict` is `null` for append topics and `{default, overrides}` (defaults materialized: omitted default → `"lww"`, omitted overrides → `{}`) for register topics; `finalityAuthority` absent → `null`.

## 8. Findings surfaced while producing these vectors

Recorded here because generating known answers forces every underspecified byte into the open. Items marked **P#** have concrete amendment text in [proposals-v3.3.md](proposals-v3.3.md); the rest need no spec change.

- **F1 (→P2)**: `topicSchemaHash` — SPEC §14 fixes the hashed field set but not the exact normalized object shape (what an absent `finalityAuthority` or an append topic's `conflict` serializes as). Section 7's values are unverifiable across implementations until ratified.
- **F2 (no change needed)**: `dec(n)` is not formally defined in §4.3. Interpretation used here — base-10 ASCII, no sign, no leading zeros, no grouping — is the only reasonable reading for non-negative safe integers; a clarifying parenthetical in the next revision wouldn't hurt but nothing hangs on it.
- **F3 (no change needed)**: the empty-string-vs-absent ambiguity for key/causal/ref is fully resolved by the `"0"`/`"1"` presence flags already in §4.3 — verified by construction in section 4.
- **F4 (→P3, documentation-only)**: unicode normalization — JCS does not normalize, so visually identical NFC/NFD strings (in payloads, keys, or topic/writer ids beyond the ASCII charter) produce different chains. Topic/WriterId are charter-restricted to ASCII so the exposure is register `Key` and payload strings. Not a defect (bytes-as-authored is the correct rule) but worth one normative sentence so no implementation "helpfully" normalizes.
- **F5 (→P1)**: seed determinism (P5) requires injectable **timers**, not just `clock()`/`rng()` — discovered in harness design, recorded in [harness.md](harness.md) §3. Listed here because it is the largest v3.3 item.
